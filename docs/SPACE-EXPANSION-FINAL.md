## 1. 两层结构

```
永恒（IP ≥ 1e308.25）
   ↓ EP ≥ 1e1200
空间膨胀（中层）
   ├─ 挑战模式：最终收益 ^0.5（可退出）
   ├─ SE（膨胀点数）：挑战内按 IP 峰值结算
   ├─ ST（膨胀时间）：按全局加成主动生产
   ├─ du1~du6：SE 复购（IP 侧加成）
   └─ du7~du11：ST 单次（换口径 / 价格 / DE 超载缓解；无最终 IP）
   ↓ EP 达到 1e3600（本阶段目标）
七巧板（现有层，不动）
   ↓ EP 峰值 ≥ 1e40
时空（外层，后续）
   └─ TP / 重置 / 永久乘区（见 §4）
```

> 为什么分两层：空间膨胀只做“抬 EP”，节奏短、反馈快；
> 时空做“重走 + 永久乘区”，不能和第一次抬 EP 混在一起（`TIMESPACE.md` §1 的理由保留）。

## 2. 空间膨胀（中层，本文重点）

### 2.1 解锁与挑战

| 项 | 规则 |
|---|---|
| 解锁 | **EP ≥ 1e1200**（2026-10-25 用户裁定；不再是「第一次永恒」） |
| 进入条件 | **EP ≥ 1e1200 后随时能进**；进入时**自动执行一次永恒重置**（保留七巧板 / 暗物质；不发 EP、不涨永恒次数） |
| 重置后 | 当前 EP / 累计 EP 清零；页面靠永久解锁记录保持可进；空间系统（SE/ST/du）保留 |
| 挑战 | 进入后**所有最终收益 ^0.5**；可随时退出 |
| 结算 | 进入时记 `challengeSeBase`；SE 按挑战内**新增 IP 峰值**增量结算；退出后停止，不再给 SE |
| 退出后 | 无 `^0.5` 削弱；已买的 du 全额生效 |
| 价格/门槛 | 挑战**不**改价格、不改上限、不改门槛（只改最终收益） |

⚠️ **`^0.5` 的作用边界必须实现成唯一入口**：
对每个“最终收益”在写回 state 之前乘一次 `challengePower`（`0.5` / `1`），
不要在公式里各处散落 `Math.sqrt`，否则又会“显示 ≠ 实发”。
`ST` 产量也是最终收益，挑战内同样吃 `^0.5`；
`SE` 是结算公式（由挑战内 IP 峰值直接算），**不再额外开方**。

**防刷口径（2026-10-25 实现决定）**：进入挑战时记录 `challengeSeBase = SE(当前IP峰值)`，
SE 只结算**挑战内新增的峰值增量**（`SE(peak) − base − 已结算`）。
⇒ 从同样的 IP 峰值反复进出**不会再拿一遍**；若要拿更多 SE，必须在挑战内把 IP 推高。

### 2.2 货币

| 货币 | 公式 | 端点 / 备注 |
|---|---|---|
| **SE** | `SE = ⌊10^(log10(IP_peak)/40 − 7)⌋` | IP 1e308 ⇒ ≈5；1e400 ⇒ 1000；1e1200 ⇒ 1e23 |
| **ST** | `dST/dt = 0.01 · log10(max(10, globalMultiplier)) · log10(1 + SE)` | 基础公式不变；**“上一轮运算结果”固定取 SE**，不随 ST 自身迭代 |

> SE 用 **IP 峰值**，不是 EP 峰值：EP 在空间膨胀前几乎不动（1.6 左右），
> 用 EP 会拿不到 SE（`TIMESPACE.md` 的旧口径已被本稿取代）。
> **ST 的上一轮结果固定为 SE**（2026-10-25 用户裁定）：
> 基础公式里递归/上一轮项不要塞 ST 自身，直接取膨胀点数。
> ST 的系数仍是**待标定**项（见 §6）。

### 2.3 du1~du6：SE 复购

| 编号 | 效果（合并稿） | 预定落点 | 位置 | 首版形状 / 价格（候选） |
|---|---|---|---|---|
| **du1** | 暗物质额外倍率 × 购买次数 | `darkMatterAdditiveTerm` | `a×`（IP 侧） | `×10^(n^1.5)`；1 SE 起，`×1.5^n` |
| **du2** | 七巧板有效加成 × 购买次数 | `tangramAxisParams` | `a×`（IP 侧） | `×10^(n^1.5)`；2 SE 起，`×1.5^n` |
| **du3** | 量子强度 × 购买次数 | 量子强度入口 | `a×`（IP 侧） | `×10^(n^1.5)`；3 SE 起，`×1.5^n` |
| **du4** | 免费 ZPE 引擎数 × 购买次数 | `effectiveEngineLevel` | `a^局部` / `a×` | `+10n` 级；4 SE 起，`×1.6^n`；**软上限 1e6 级** |
| **du5** | 七巧板熵→粒子倍率 × 购买次数 | `conversion` / `tangramConvRateMult` | `a×` | `×10^(√n)`；5 SE 起，`×1.6^n` |
| **du6** | 计数频率倍率（次数的开根） | `countFreqAddTerm` | `a×` | `×(1 + 0.5√n)`；6 SE 起，`×1.6^n`；**软上限 1e8 级** |

> `du4~du6` 的形状是**辅助项**，不承担主预算；主预算由 du1~du3 承担（见 §2.5）。
>
> **du4/du6 软上限（2026-10-25 用户裁定 + 选定公式）**：
> - du4 在 **1e6 级**、du6 在 **1e8 级**进入软上限（记为 `C`）；
> - 超过后**仍可继续购买，总效果继续增加**；
> - 把超出部分按**平均每级效率**折算成“等效等级”：
>   ```text
>   n_eff = n                                      , n <= C
>   n_eff = C + (n - C) / (1 + 0.5·log10(n/C))    , n > C
>   ```
> - 因此：
>   - du4：`n = 1e8`（`C×100`）时，超出部分的平均每级效果 = **初值的 50%**；
>   - du6：`n = 1e10` 时同理 = **50%**；
> - 之后继续按同一曲线递减，**不是硬停，也不是总效果直接减半**；
> - du4 用 `+10·n_eff`、du6 用 `×(1 + 0.5·√n_eff)`；买满可闭式算。
>
> ⚠️ 这里“50%”指**从 C 到该等级的平均每级效率**；如果你要的是**逐级边际**严格在
> 那一点恰好 50%，需要改成数值积分，本稿先采用可闭式的等效等级。

### 2.4 du7~du11：ST 单次

| 编号 | 效果（合并稿） | 预定落点 | 位置 | ST 价格（候选） |
|---|---|---|---|---|
| **du7** | **膨胀自动化**：单次解锁 du1~du6 的自动购买；开关在梦想（自动化）页，买下后仍需手动打开 | 梦想（自动化）页 | `结构`（自动化） | 10 |
| **du8** | ZPE 倍率削弱 ZPE 引擎价格（渐近 10%） | `zpeEngineCost` | `结构`（价格） | 100 |
| **du9** | 虚空升级强度 ∝ `log10(量子数)`（封顶 ×10；当前落在 `voidBoostMult`） | 虚空升级效果 | `a×` | 1e3 |
| **du10** | ZPE 倍率对膨胀升级价格修正 | 膨胀升级价格 | `结构`（价格） | 1e4 |
| **du11（新）** | **单次**：用 ST 抬高**有效 DE 倍率**的削弱下限；初始保留 0.3×原始强度，随 ST 升高但封顶 0.95，不会到 1 | `darkEnergyMultiplier` 有效量 | `结构`（环） | **1e5 ST · 单次** |

> **新 du11（2026-10-25 定稿）**：
> - **单次购买**，没有等级；
> - **唯一变量是当前膨胀时间 ST**；价格和初始基准是固定常数；
> - 候选公式（`C = 1e5 ST` 为购买价/基准）：
>   ```text
>   floor(ST) = min(0.95,
>                    0.3 + 0.7 · max(0, ST − C) / (max(0, ST − C) + C))
>   ```
>   - 当前 ST=C ⇒ 0.3；ST=2C ⇒ 0.65；ST=10C ⇒ 0.936；
>   - 封顶 **0.95**，永远留 5% 削弱，不会完全等于无削弱；
> - 0.3 是“**被削弱后的强度下限**”，不是“削减量 0.3”。
> - **落点（2026-10-25 归一化后）**：`darkEnergyMultiplier` 的有效量
>   `L_eff' = max(L_eff, floor(ST) × L_raw)`；
>   因为 DE 项与 log 线性，等价于“倍率至少保留 floor 的比例”。
>   **不再接 `overloadFactor()`（物质超载）**；matterSpanMult 的 cap 暂不跟 du11。
> - ST 指**购买后的当前持有量**；若之后被其他升级花掉，floor 会随当前 ST 回落。

> **du7（2026-10-25 定稿）**：不再改量子口径，改为**单次解锁 du1~du6 的自动购买**。
> 自动化开关固定放在梦想（自动化）页；买下 du7 只是解锁能力，仍需手动开。
> 自动购买只花 SE，按游戏时间、与帧率无关（`SPACE_DU_AUTO.buyPerSecond = 100` 级/秒/条）。
>
> **实现状态**：du1~du6、du9、du11 已接；du7 自动化解锁已接；du8/du10 仍按 IP 禁令暂缓。

### 2.5 阶数预算（按当前代码重算）

> ⚠️ 2026-10-25 实测 EP=1e1296 ⇒ 本节以 **1e10 为目标的表只保留作历史基准**；
> 当前阶段目标已改为 **1e3600**，新预算见 §2.7。

当前代码的第一块七巧板门槛是 **1e10 EP**（`TANGRAM_ACQUIRE.epThresholds[0]`），
不是旧稿的 1e8。EP 公式：

```
EP = 5^(log10(IP)/308 − 0.7)
⇒ log10(IP_target) = 308 × (log10(EP_target)/log10(5) + 0.7)
```

| 目标 EP | 需要的 `log10(IP)` | 比首次永恒（308.25）多 |
|---:|---:|---:|
| 1e8（旧稿） | 3740.7 | **+3432.4 阶** |
| **1e10（当前代码）** | 4621.8 | **+4313.6 阶** |
| 1e40（时空解锁线） | 17842 | +17534 阶（不由本层负责） |

`du1~du3` 都是 `×10^(n^1.5)` 时，三者相乘的总指数是：

```
E = n1^1.5 + n2^1.5 + n3^1.5
```

等量购买 `n` 时 `E = 3·n^1.5`：

| 目标 EP | 每条 n | 总 IP 阶数 | 累计 SE（`×1.5^n`，三条合计） |
|---:|---:|---:|---:|
| 1e8 | 110 | 3·110^1.5 ≈ +3461 | ≈1.4e20 |
| **1e10** | **128** | 3·128^1.5 ≈ +4344 | ≈2.1e23 |

> ⚠️ `SPACE-EXPANSION.md` §12.6 的 228 次是**单条** `10^(n^1.5)` 达到 +3434 阶；
> 若三条同形相乘，应该每条 ≈110 次（1e8）或 ≈128 次（1e10），不是「228 总量按 76 分」。
> 76^1.5×3≈1988 阶，不够 +3434；原表那一句需要按本表修正。
>
> ⚠️ 本表是**等效 IP 阶数预算**：du1/du2/du3 分别经过暗物质 / 七巧板 / 量子，
> 不是同一个乘区；实际转化效率不同。实装后必须用 `stage-timing` 的 IP 峰值反推真实 n，
> 不能把三条都当成“直接 ×10^(n^1.5) 到 IP”。

**SE 自洽**：目标 1e10 需要约 2.1e23 SE；
`SE = 10^(log10(IP)/40 −7)` ⇒ IP 1e1200 时约 1e23，IP≈1e1213 时约 2.1e23，
仍在空间膨胀的 IP 阶梯内（不需要外部货币）。

### 2.7 EP 1e3600 重算（2026-10-25 实测修正）

> **实测：挂机数日后 EP 已达 1e1296。** 这推翻了上一版把“静态模型 20 轮只到
> 1e498 / c=0.1 卡死”当成“1e3600 不可达”的结论。下面把基线改成**当前实测**：
> EP 1e1296 ⇒ `log10(IP) ≈ 571,296`；到 1e3600 还差约 **1,015,254 个 IP 阶**。
> 旧表（从首次永恒 1e308 起算）只保留作历史下界，不再当作可行性证明。

`EP = 5^(log10(IP)/308 − 0.7)`：

| 基线 | `log10(IP)` | 到 1e3600 还差 | 三条 du 均分每条 n |
|---|---:|---:|---:|
| 首次永恒 1e308.25 | 308.25 | +1,586,241.5 阶 | 6,539 |
| 原七巧板门槛 1e10 | 4,622.1 | +1,581,927.7 阶 | 6,530 |
| **实测当前 EP 1e1296** | **571,295.9** | **约 +1,015,254 阶** | **≈4,857** |

- 按三条 du 各承担 1/3、且按 `×10^(n^1.5)` **直接 1:1 转成 IP 阶数**，
  从当前档到 1e3600 每条约 **4,857 次**（合计 ≈14,571 次）；
- 单次价格 `1.5^4857 ≈ 1e855`；目标处 `SE ≈ 1e39,656.7`，
  买得起仍然不是瓶颈；
- **真正未知的仍是 du1~du3 → IP 的实际转化系数**：du1 落暗物质加法项、
  du2 落七巧板有效加成、du3 落量子强度，不是直接乘 IP。实测 EP 1e1296
  证明“整体闭环能涨”，但不等于这三条 du 能按 1:1 兑现 101 万阶。

**结论修正**：不再说“1e3600 绝对不可达”；改为：
1. 现有闭环 + 挂机已到 1e1296，目标 1e3600 有现实基线；
2. 但空间 du 的转化率与软上限仍未实测，**不能据此直接上线**；
3. 必须用真引擎从当前 EP 1e1296 起跑，测 du1~du3 的实际增益，再决定 n/价格。

**关键：du1~du3 不是直接乘 IP。**  
du1 落暗物质加法项、du2 落七巧板有效加成、du3 落量子强度；
它们到 IP 之间还隔着暗能量/物质/量子/引擎和**现成软上限**。
上表的 4,857 是“等效 IP 阶数预算”，不是实际可达到的值。

用最乐观的“等效”模型（`SE=10^(L/40−7)`，价格 `base×1.5^n`，
效果 `L += c·Σn^1.5`）从**旧起点 1e308** 跑 20 轮，只能看敏感度，
**不能外推到实测 EP 1e1296**：

| 转换系数 `c` | 20 轮后 `log10(IP)` | 对应 EP | 旧模型内的结果 |
|---:|---:|---:|---|
| 1.0（1:1，理想） | ≈2.20e5 | ≈1e498 | 远低于 1e3600 |
| 0.1 | ≈310.2 | ≈1.6 | 旧起点卡死 |
| 0.01 | ≈308.4 | ≈1.6 | 基本不动 |

> ⚠️ 2026-10-25 实测 EP=1e1296 ⇒ 这组“卡死”数字**已被真实闭环推翻**：
> 现有系统（挂机 / 自动 / 巧板 / 无限长河等）本身就能把 EP 推过 1e1000。
> 因此它只能证明“从 1e308 起、只靠这套 du、且 c≤0.1 的静态模型不够”，
> **不能**证明“1e3600 不可达”，也不能证明 du 的实际转化率。

**`epMult` 不能替代 du 的 IP 阶数**（虽然它是本阶段唯一允许的 EP 倍率）：

| `epMult` 等级 | 需要 `log10(IP)` | 相对无 epMult 减少 | 备注 |
|---:|---:|---:|---|
| 0 | 1,586,549.8 | — | 基准 |
| 1000 | 1,278,549.8 | 仅 19% | 成本 ≈1e2699 EP，效果 1e699 |
| ≈1334（成本 ≈1e3600 时） | 1,175,677.8 | 26% | 成本吃光目标 EP |

`epMult` 的价格末段是 ×500/级、效果 ×5/级 ⇒ **成本涨得比效果快**，
它只能在高 EP 之后放大，不能替空间 du 补上 101 万阶 IP。

**结论（修正）：当前不能把“1e3600 不可达”当结论，但仍不能直接上线。** 缺的是：

1. **真实转化系数**：du1~du3 到 IP 的转化率没有实测，不能用“等效 1:1”当预算；
2. **从当前档复测**：需要拿真引擎从 EP 1e1296 起跑，测 du1~du3 + 软上限能否补上 101 万阶；
3. **上限/收敛设计**：`×10^(n^1.5)` 的效果增长远快于 `×1.5^n` 的价格，
   在目标附近极易从“爬不动”直接变成“跑飞”；必须先定 knee/cap 与 `p` 验收；
4. **口径**：上述 1e1296 是当前完整闭环的实测；现有 `em5` / `ipTime` / 巧板 IP 奖励
   **已裁定保留**，因此可作为当前基线；但空间 du 本身的转化率仍需单独复测。

> ⚠️ 约束检查：合并稿**没有直接 EP 倍率**（`TIMESPACE` 的 A/C 已删），
> du1~du11 里 du1~du7/du9/du11 落在环上，du8/du10 是价格侧；唯一 EP 倍率是 `epMult` ✓
> 因此“禁止除永恒升级外的 EP 倍增手段”**满足**，但也意味着
> 空间膨胀必须自己把 IP 推到 ≈1e1.586e6，不能靠乘 EP 走捷径。

### 2.8 IP 倍率禁令合规（2026-10-25 已定）

**规则（用户裁定）**：IP 禁令只约束**新增的空间 upgrade**；
`em5` / `ipTime` / 巧板 `ipDoubleKneeMult` / `passiveIpFrac` 等**现有** IP 侧系统
**不按禁令关闭**，继续保留。

| 项 | 结论 | 处理 |
|---|---|---|
| **旧 du11** `IP × ST^0.1` | ❌ 直接 IP 倍率 | **删除**；新 du11 改成 DE 超载缓解（见 §2.4） |
| **新 du11** DE 超载缓解 | ✅ 暗能量环，不是 IP 倍率 | 保留；强度下限 0.3×初始 → 封顶 0.95 |
| **du8** ZPE 引擎价格折扣 | ⚠️ 价格侧，不是环转化速率 | **暂缓**；若要严格“只允许环速率”，本阶段不实现 |
| **du10** 膨胀升级价格修正 | ⚠️ 价格侧 | **暂缓** |
| **du2** 巧板有效加成 | ⚠️ 若包含 `ipDoubleKneeMult` / `passiveIpFrac` 就是 IP 侧 | 只允许 `deKneeMult` / `convSlopeMult` 等**非 IP** 的巧板效果；IP 相关项排除 |
| **du4** 免费引擎等级 | 引擎 `engineBonusMult` 会进 `quantumToIPGain`（量子铸币） | 保留；这是既有量子铸币链路，不新增独立 IP 倍率 |
| **du1/du3/du5/du6/du7/du9** | ✅ 环：暗物质 / 量子强度 / 凝聚 / 计数频率 / 量子口径 / 虚空 | 保留，但都要过环增益与软上限 |
| **`em5`（永恒里程碑 5）** | ✅ 现有 IP 倍率 | **保留，不关闭** |
| **`ipTime`（无限长河）** | ✅ 现有 IP 收入 | **保留，不关闭** |
| **`ipDoubleKneeMult` / `passiveIpFrac`（巧板奖励）** | ✅ 现有 IP 侧奖励 | **保留，不关闭** |

**结论**：IP 倍率口径已经拍板，不再有“em5 必须先关”的阻塞项。

> ⚠️ 但仍有一个未决的平衡问题：新 du11 的 1e5 ST 单次价格、0.3→0.95 的
> 具体响应曲线、du4/du6 的等效等级公式，都需要引擎侧复测；§2.7 的 101.5 万阶
> 也仍必须用真实引擎验证，不能只靠 1:1 预算。

## 5. 实装顺序（建议）

1. `config`：新增空间膨胀表（SE / ST / du1~du11 / 价格），**唯一数据源**；

### 验收（实装时写进断言）

- SE：`IP_peak=1e308 ⇒ 5`、`1e400 ⇒ 1000`、`1e1200 ⇒ ~1e23`；
- 解锁：`EP < 1e1200` 时不可进入；`EP ≥ 1e1200` 解锁；
- 空间膨胀从当前 EP 1e1296 到 1e3600，轮次**待标定**；每轮 ≤15 分钟；
