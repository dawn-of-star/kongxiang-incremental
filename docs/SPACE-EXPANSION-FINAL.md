## 0. 合并结论（先看这 7 条）

1. **空间膨胀 = 中层**，唯一职责：把 EP 抬到七巧板第一块的门槛；
   **不负责**重走主循环（那是时空层）。
2. 保留 **du1~du11**；`TIMESPACE` 的「空间张量 / EP 指数」两升级**删除**，
   因为它们会与 du 的 IP 阶梯重复计算 EP。
3. 货币保留 **SE（膨胀点数）+ ST（膨胀时间）**：
   - SE：挑战内抵达 `IP ≥ 1e308.25` 时结算；
   - ST：由全局加成主动生产。
4. 挑战 `所有最终收益 ^0.5` **只在挑战内生效**；退出后全额；SE 只在挑战内结算。
5. **du1~du3 是主推手**：效果用购买次数上的超指数 `×10^(n^1.5)`；
   du4~du6 是辅助的 SE 复购；du7~du11 是 ST 单次购买。
6. 目标 EP **不写死 1e8**：读 `TANGRAM_ACQUIRE.epThresholds[0]`
   （当前代码是 **1e10**，不是旧稿的 1e8）⇒ du 的阶数预算按当前门槛重算。
7. 时空层（TP / 重置 / 永久乘区）**保留为下一层**，等空间膨胀验收通过后再做；
   它不参与这次“抬 EP”的闭环。

## 1. 两层结构

```
永恒（IP ≥ 1e308.25）
   ↓ 第一次永恒后解锁
空间膨胀（中层）
   ├─ 挑战模式：最终收益 ^0.5（可退出）
   ├─ SE（膨胀点数）：挑战内按 IP 峰值结算
   ├─ ST（膨胀时间）：按全局加成主动生产
   ├─ du1~du6：SE 复购（IP 侧加成）
   └─ du7~du11：ST 单次（换口径 / 价格 / 最终 IP）
   ↓ EP 峰值达到第一块七巧板门槛（当前 1e10）
七巧板（现有层，不动）
   ↓ EP 峰值 ≥ 1e40
时空（外层，后续）
   └─ TP / 重置 / 永久乘区（见 §4）
```

> 为什么分两层：空间膨胀只做“抬 EP”，节奏短、反馈快；
> 时空做“重走 + 永久乘区”，不能和第一次抬 EP 混在一起（`TIMESPACE.md` §1 的理由保留）。

## 2. 空间膨胀（中层，本文重点）

### 2.1 解锁与挑战

| 项 | 规则 |
|---|---|
| 解锁 | 第一次永恒（`IP ≥ ETERNITY.goalLog10 = 308.25`）之后 |
| 挑战 | 进入后**所有最终收益 ^0.5**；可随时退出 |
| 结算 | SE 只在挑战内按 **IP 峰值** 结算；退出后按挑战内峰值给，退出后不再给 SE |
| 退出后 | 无 `^0.5` 削弱；已买的 du 全额生效 |
| 价格/门槛 | 挑战**不**改价格、不改上限、不改门槛（只改最终收益） |

⚠️ **`^0.5` 的作用边界必须实现成唯一入口**：
对每个“最终收益”在写回 state 之前乘一次 `challengePower`（`0.5` / `1`），
不要在公式里各处散落 `Math.sqrt`，否则又会“显示 ≠ 实发”。
`ST` 产量也是最终收益，挑战内同样吃 `^0.5`；
`SE` 是结算公式（由挑战内 IP 峰值直接算），**不再额外开方**。

### 2.2 货币

| 货币 | 公式 | 端点 / 备注 |
|---|---|---|
| **SE** | `SE = ⌊10^(log10(IP_peak)/40 − 7)⌋` | IP 1e308 ⇒ ≈5；1e400 ⇒ 1000；1e1200 ⇒ 1e23 |
| **ST** | `dST/dt = 0.01 · log10(max(10, globalMultiplier)) · log10(1 + SE)` | **候选**；原 `SPACE` 用 `·SE`，在 SE=1e40 时会让单次价格瞬间失效，故改为 `log10(1+SE)` |

> SE 用 **IP 峰值**，不是 EP 峰值：EP 在空间膨胀前几乎不动（1.6 左右），
> 用 EP 会拿不到 SE（`TIMESPACE.md` 的旧口径已被本稿取代）。
> ST 的系数仍是**待标定**项（见 §6）。

### 2.5 阶数预算（按当前代码重算）

当前代码的第一块七巧板门槛是 **1e10 EP**（`TANGRAM_ACQUIRE.epThresholds[0]`），
不是旧稿的 1e8。EP 公式：

```
EP = 5^(log10(IP)/308 − 0.7)
⇒ log10(IP_target) = 308 × (log10(EP_target)/log10(5) + 0.7)
```

| 目标 EP | 需要的 `log10(IP)` | 比首次永恒（308.25）多 |
|---:|---:|---:|
| 1e8（旧稿） | 3740.7 | **+3432.4 阶** |
| **1e10（当前代码）** | 4621.8 | **+4313.6 阶** |
| 1e40（时空解锁线） | 17842 | +17534 阶（不由本层负责） |

`du1~du3` 都是 `×10^(n^1.5)` 时，三者相乘的总指数是：

```
E = n1^1.5 + n2^1.5 + n3^1.5
```

等量购买 `n` 时 `E = 3·n^1.5`：

| 目标 EP | 每条 n | 总 IP 阶数 | 累计 SE（`×1.5^n`，三条合计） |
|---:|---:|---:|---:|
| 1e8 | 110 | 3·110^1.5 ≈ +3461 | ≈1.4e20 |
| **1e10** | **128** | 3·128^1.5 ≈ +4344 | ≈2.1e23 |

> ⚠️ `SPACE-EXPANSION.md` §12.6 的 228 次是**单条** `10^(n^1.5)` 达到 +3434 阶；
> 若三条同形相乘，应该每条 ≈110 次（1e8）或 ≈128 次（1e10），不是「228 总量按 76 分」。
> 76^1.5×3≈1988 阶，不够 +3434；原表那一句需要按本表修正。
>
> ⚠️ 本表是**等效 IP 阶数预算**：du1/du2/du3 分别经过暗物质 / 七巧板 / 量子，
> 不是同一个乘区；实际转化效率不同。实装后必须用 `stage-timing` 的 IP 峰值反推真实 n，
> 不能把三条都当成“直接 ×10^(n^1.5) 到 IP”。

**SE 自洽**：目标 1e10 需要约 2.1e23 SE；
`SE = 10^(log10(IP)/40 −7)` ⇒ IP 1e1200 时约 1e23，IP≈1e1213 时约 2.1e23，
仍在空间膨胀的 IP 阶梯内（不需要外部货币）。

### 2.6 `p` 预算

`SPACE-EXPANSION.md` §4 的预算保留：

挑战内 p ≤ 0.5；挑战外 p ≤ 0.35
du1/du5 不在 IP 环上 ⇒ 0
du2/du3/du4/du6 各 ≤ 0.10 级别

### 2.7 `EP = 1e3600` 可行性（未通过，禁止上线）

先算目标。`EP = 5^(log10(IP)/308 − 0.7)`，所以：

| 目标 EP | 需要 `log10(IP)` | 比首次永恒多 | 三条 du 均分时每条 n |
|---:|---:|---:|---:|
| 1e10（当前七巧板门槛） | 4,622.1 | +4,313.8 阶 | 128 |
| **1e3600** | **1,586,549.8** | **+1,586,241.5 阶** | **6,539** |

- 1e3600 需要 **+158.6 万个 IP 数量级**，是 1e10 目标的 **368 倍订单量**；
- 若按三条 du 各承担 1/3、且按 `×10^(n^1.5)` **直接 1:1 转成 IP 阶数**，
  每条要买 **≈6,539 次**（合计 ≈19,617 次），
  单次价格 `1.5^6539 ≈ 1e1151.5`；
- 目标处 `SE = 10^(1,586,549.8/40−7) ≈ 1e39,656.7`，
  所以“买得起”不是问题 —— **问题是从 1e308 到 1e1.586e6 的反馈过程是否真的能爬上去**。

**关键：du1~du3 不是直接乘 IP。**  
du1 落暗物质加法项、du2 落七巧板有效加成、du3 落量子强度；
它们到 IP 之间还隔着暗能量/物质/量子/引擎和**现成软上限**。
上表的 6,539 是“等效 IP 阶数预算”，不是实际可达到的值。

用最乐观的“等效”模型（`SE=10^(L/40−7)`，价格 `base×1.5^n`，
效果 `L += c·Σn^1.5`）跑迭代，可以看清对转换系数 `c` 的敏感度：

| 转换系数 `c` | 20 轮后 `log10(IP)` | 对应 EP | 结果 |
|---:|---:|---:|---|
| 1.0（1:1，理想） | ≈2.20e5 | ≈1e498 | 20 轮仍远未到 1e3600 |
| 0.1 | ≈310.2 | ≈1.6 | **直接卡死**（和首次永恒同一量级） |
| 0.01 | ≈308.4 | ≈1.6 | 基本不动 |

⇒ 只要 du1~du3 的实际 IP 转化效率低于约 0.1（非常可能，因为要过暗能量/七巧板/量子的软上限），
这套阶梯**根本爬不起来**；即使按 1:1，20 轮也只到 1e498，离 1e3600 还差 3,100 个 EP 数量级。

**`epMult` 不能当助推器**（虽然它是本阶段唯一允许的 EP 倍率）：

| `epMult` 等级 | 需要 `log10(IP)` | 相对无 epMult 减少 | 备注 |
|---:|---:|---:|---|
| 0 | 1,586,549.8 | — | 基准 |
| 1000 | 1,278,549.8 | 仅 19% | 成本 ≈1e2699 EP，效果 1e699 |
| ≈1334（成本 ≈1e3600 时） | 1,175,677.8 | 26% | 成本吃光目标 EP |

`epMult` 的价格末段是 ×500/级、效果 ×5/级 ⇒ **成本涨得比效果快**，
它只能在高 EP 之后放大，不能把 1e10 直接抬到 1e3600。

**结论：当前空间膨胀不能上线。** 至少缺三块：

1. **真实转化系数**：du1~du3 到 IP 的转化率没有实测，不能用“等效 1:1”当预算；
2. **1e3600 的反馈模型**：需要拿真引擎跑 du1~du3 + 软上限，确认能爬过 1e5~1e6 阶；
3. **上限/收敛设计**：`×10^(n^1.5)` 的效果增长远快于 `×1.5^n` 的价格，
   在目标附近极易从“爬不动”直接变成“跑飞”；必须先定 knee/cap 与 `p` 验收。

> ⚠️ 约束检查：合并稿**没有直接 EP 倍率**（`TIMESPACE` 的 A/C 已删），
> du1~du11 都是 IP 侧 / 价格侧 / 最终 IP；唯一 EP 倍率是 `epMult` ✓
> 因此“禁止除永恒升级外的 EP 倍增手段”**满足**，但也意味着
> 空间膨胀必须自己把 IP 推到 ≈1e1.586e6，不能靠乘 EP 走捷径。

## 3. 与旧稿的差异决议

| 旧稿项 | 处理 | 理由 |
|---|---|---|
| `TIMESPACE` 的 A「空间张量 EP ×1e8」 | **删除** | 和 du 的 IP 阶梯重复抬 EP；保留会让 EP 双倍膨胀 |
| `TIMESPACE` 的 B「下次价格 ×1.8」 | **合并**为 du 的 SE 价格增长 | 统一到 `×1.5^n` / `×1.6^n` |
| `TIMESPACE` 的 C「EP 指数 +0.0002√SE」 | **删除** | 同上，避免二次改 EP 公式 |
| SE 按 EP 峰值 | 改为按 **IP 峰值** | EP 在膨胀前几乎不动；IP 才是涨的量 |
| 目标 EP = 1e8 | 改为读 `epThresholds[0]`（当前 1e10） | 旧稿 1e8 已过期；不写死 |
| `SPACE-EXPANSION` 的 du1~du11 | **保留** | 这是主设计 |
| `TIMESPACE` 的时空层（TP/重置/三升级） | **保留为外层** | 与空间膨胀职责不冲突，后续实现 |

> ⚠️ 如果以后把七巧板第一块门槛降到 1e8，只需把 §2.5 的 n 从 128 改到 110；
> **不要**在两处各写一个目标值。

## 5. 实装顺序（建议）

1. `config`：新增空间膨胀表（SE / ST / du1~du11 / 价格），**唯一数据源**；
2. `state`：`se`、`st`、`spaceUpgrades`、`spaceChallenge`、`spaceBestIp`、`spaceBestEp` 等字段 + 存档；
3. `engine`：`spaceGain(state)`、`buySpaceUpgrade(id)`、挑战进出、最终收益 `^0.5` 的唯一包装；
4. `ui`：空间膨胀页（SE/ST、du 卡片、挑战开关、下一次结算预览）；
5. 断言：SE 端点、du 单调/价格、挑战 `^0.5`、退出后全额、`p` 实测；
6. 时空层等以上验收通过后再做。

### 验收（实装时写进断言）

- SE：`IP_peak=1e308 ⇒ 5`、`1e400 ⇒ 1000`、`1e1200 ⇒ ~1e23`；
- 空间膨胀从 1.6 EP 到 `epThresholds[0]`，**≤10 轮**、每轮 ≤15 分钟；
- du1~du3 的阶数表与 §2.5 一致（偏差 <5%）；
- 挑战内 `^0.5` 只改最终收益，不改价格/门槛/上限；
- 退出挑战后 du 全额生效，SE 不重复结算；
- `p` 挑战内 ≤0.5、挑战外 ≤0.35。
