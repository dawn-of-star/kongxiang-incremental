## 4. 评估：三个必须现在就定的问题

### ① `^0.5` 作用在一个**明确集合**上，不能是"所有收益"

`x^0.5` 是**凹函数** ⇒ 压缩大数、抬小数 ⇒ 数学上**安全**（不会把 `p` 推向 1 ✓）。
但"所有最终收益"太宽 ✗：如果连 **IP 收益**也开根 ⇒ 永恒门槛 `1e308.25` 变成 `1e616.5` ✗ 直接不可达 ✗✗

**必须排除**（我的建议）：
| 排除项 | 理由 |
|---|---|
| IP 收益（`bigCrunchGain`）| 开根后永恒门槛翻倍 ⇒ 不可达 ✗ |
| EP 收益（永恒给的那部分）| 同上（SE 的获取依赖 EP 峰值 ✓ 需要它可达）|
| 七巧板覆盖率 → 三轴 | 开根会破坏"端点 10~10000 / 0.05~50"的既有约束 ✗ |

**可以吃 `^0.5`**：暗能量收益、ZPE 引擎产出、熵→粒子速率、计数频率这类**层内收益** ✓
⇒ 建议把稿子里的"所有最终收益"改成**明确的清单**（我给你一份候选，你划✓）

### ② du3 / du6 都可能**把 `p` 推向 1**，必须核算

- **du3**（量子强度 ∝ 购买次数）：量子 → IP 是一条**已经存在的**链 ⇒ 乘区本身安全 ✓；但如果"购买次数"无上限且乘区是**线性**，长期会让 IP 增长**超线性** ✗
  ⇒ **建议加 knee**：`1 + A·x/(1+x)`（饱和）而不是 `×次数` ✓
- **du6**（虚空升级强度 ∝ 量子数量）：若虚空升级里有"IP 倍率"，而量子数量又随 IP 增长 ⇒ **IP → 量子 → 虚空 → IP** 的闭环 ✗✗ 这是最危险的一条
  ⇒ **必须**：① 只看**量子数量**的 `log10` ② 加硬封顶 ③ 落在我给你确认过的"非 IP 环"的虚空升级上 ✓

### ③ du5 是"改价格"，要防**价格 → 0**

`ZPE 引擎价格 ×(1−k)`，若 `k → 1` ⇒ 免费 ✗ ⇒ 无限买 ✗
⇒ **建议**：`价格 × (1 / (1 + 0.02·ST))`（永远 > 0，但逐渐趋近 0 的极限为 0 ✗ hmm）…
**更稳的写法**：`价格 × max(0.1, 1 − 0.05·ST)`（下限 10%）✓ 或改用 knee：`价格 × (1 − 0.9·x/(1+x))`（渐近到 10%）✓

## 6. 验收口径（写进断言）

1. **模式内 `^0.5` 只作用于清单内的量**（清单外的量在模式内外**数值相同** ✓）
2. 挑战模式 **不改变 `p`**（`ip-economy-lab` 实测 `p` 仍在安全区 ✓）
3. du1~du3 的 knee **单调 + 封顶**（`x→∞` 时趋于 `1+A` ✓）
4. du4 换口径后 **量子加成 ≥ 换口径前**（改革不能是削弱 ✓）
5. du5 的价格**永远 > 0**（下限 10% ✓）
6. du6 的闭环**不存在**：开关 du6 前后 `p` 变化 < 1e-6 ✓
7. 从首次永恒到 EP ≥ 1e8 **≤ 12 轮**（每轮 ≤ 15 分钟，`stage-timing` 实测 ✓）

## 7. 我的总体判断

**这套比我的三层草案好**，理由：
- ✅ 用**挑战模式**做"压缩"⇒ 主题成立（膨胀 = 空间被撑开 ⇒ 单位体积收益变小 ✓）、且天然解释了"为什么进了这层反而变弱"
