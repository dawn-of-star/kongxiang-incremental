## 4. 评估：三个必须现在就定的问题

### ① `^0.5` 作用在一个**明确集合**上，不能是"所有收益"

`x^0.5` 是**凹函数** ⇒ 压缩大数、抬小数 ⇒ 数学上**安全**（不会把 `p` 推向 1 ✓）。
但"所有最终收益"太宽 ✗：如果连 **IP 收益**也开根 ⇒ 永恒门槛 `1e308.25` 变成 `1e616.5` ✗ 直接不可达 ✗✗

**必须排除**（我的建议）：
| 排除项 | 理由 |
|---|---|
| IP 收益（`bigCrunchGain`）| 开根后永恒门槛翻倍 ⇒ 不可达 ✗ |
| EP 收益（永恒给的那部分）| 同上（SE 的获取依赖 EP 峰值 ✓ 需要它可达）|
| 七巧板覆盖率 → 三轴 | 开根会破坏"端点 10~10000 / 0.05~50"的既有约束 ✗ |

**可以吃 `^0.5`**：暗能量收益、ZPE 引擎产出、熵→粒子速率、计数频率这类**层内收益** ✓
⇒ 建议把稿子里的"所有最终收益"改成**明确的清单**（我给你一份候选，你划✓）

### ② du3 / du6 都可能**把 `p` 推向 1**，必须核算

- **du3**（量子强度 ∝ 购买次数）：量子 → IP 是一条**已经存在的**链 ⇒ 乘区本身安全 ✓；但如果"购买次数"无上限且乘区是**线性**，长期会让 IP 增长**超线性** ✗
  ⇒ **建议加 knee**：`1 + A·x/(1+x)`（饱和）而不是 `×次数` ✓
- **du6**（虚空升级强度 ∝ 量子数量）：若虚空升级里有"IP 倍率"，而量子数量又随 IP 增长 ⇒ **IP → 量子 → 虚空 → IP** 的闭环 ✗✗ 这是最危险的一条
  ⇒ **必须**：① 只看**量子数量**的 `log10` ② 加硬封顶 ③ 落在我给你确认过的"非 IP 环"的虚空升级上 ✓

### ③ du5 是"改价格"，要防**价格 → 0**

`ZPE 引擎价格 ×(1−k)`，若 `k → 1` ⇒ 免费 ✗ ⇒ 无限买 ✗
⇒ **建议**：`价格 × (1 / (1 + 0.02·ST))`（永远 > 0，但逐渐趋近 0 的极限为 0 ✗ hmm）…
**更稳的写法**：`价格 × max(0.1, 1 − 0.05·ST)`（下限 10%）✓ 或改用 knee：`价格 × (1 − 0.9·x/(1+x))`（渐近到 10%）✓

## 8. 问题 2 的答案：`p` 怎么压到 0.5 以内（**不改原机制**，只削弱）

### 8.1 挑战模式本身就把 `p` 砍一半

`最终收益 ^0.5` 在 **log 空间**上就是"斜率 × 0.5"⇒
```
实测 p ≈ 0.301  ⇒  模式内 p_eff ≈ 0.301 × 0.5 ≈ 0.150   ✓（远低于 0.5）
```
⇒ **挑战模式 = 天然的 p 抑制器** ✓ 这就是"允许退出"但"想强就得进"的机制张力 ✓

### 8.2 du1~du6 的 **p 预算表**（每条允许贡献多少 log 斜率）

| 编号 | 作用对象 | 是否在 IP 环上 | 允许的 p 增量 | 做法 |
|---|---|---|---|---|
| du1 | 暗物质额外倍率 | 否（DE → 物质）| 0 | 直接乘 ✓ |
| du2 | 七巧板三轴 | **是**（引擎/转化/计数 → IP）| ≤ 0.05 | **knee 化**（`1 + A·x/(1+x)`）|
| du3 | 量子强度 | **是**（量子 → IP）| ≤ 0.05 | **knee 化** + 只看 `log10(购买次数)` |
| du4 | 量子加成改按个数 | **是** | ≤ 0.10 | 换口径后**只放大常数项**（不改指数）|
| du5 | ZPE 价格 | 否 | 0 | 价格 × 渐近 10% ✓ |
| du6 | 虚空升级强度 | **是**（量子 → 虚空 → IP）| ≤ 0.10 | 只看 `log10(量子数)` + 硬封顶 |
| **合计** | | | **≤ 0.30** | ⇒ `p_eff ≤ 0.15 + 0.30 = 0.45 < 0.5` ✓ |

**验收**：`ip-economy-lab` 实测 p，**模式内 ≤ 0.5**、**模式外 ≤ 0.35** ✓（超了就把对应 du 的 knee 收紧）

## 9. 补一条必须有的升级：**du7（EP 除数）**

**为什么必须有**（这是你稿子里唯一的硬缺口）：

```
EP = 5^(log10(IP)/308 − 0.7)
⇒ log10(EP) 对 log10(IP) 的斜率 = 0.699 / 308 ≈ 0.00227
⇒ 要让 EP 从 1.6 涨到 1e8（Δlog10 = 7.8）⇒ 需要 IP 再涨 **3436 个数量级** ✗✗
```

而 du1~du6 **全部喂 IP**、没有一个直接抬 EP ✗ ⇒ 七巧板的 `1e8 EP` 永远够不到 ✗

**du7（单次购买，ST）：把 EP 公式里的除数从 308 降到 26**，分 4 档：

| 档 | D | `IP = 1e308.25` 时的 EP | 价格（ST）|
|---|---|---|---|
| 0 | 308 | 1.62 | — |
| 1 | 200 | 3.9 | 10 |
| 2 | 120 | 20.5 | 100 |
| 3 | 60 | 1230 | 1000 |
| 4 | 26 | **4.2e7** | 10000 |

⇒ **4 档就跨完 7.8 个数量级** ✓ 且是**结构性**（改除数，不改 p）✓
⇒ 一旦 IP 超过 `1e308.25`（时空层会给），EP 还会更高 ✓
